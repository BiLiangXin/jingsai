# S04-CLARIFY-02 — fixed source mapping method before acoustic run

Scope: only the 20 aligned Attachment4 records and their matching official MP4 files. Preserve the existing private 20-row `attachment4_predictions_explanations_PARTIAL.csv` byte for byte. This method adds a separate mapping table; it does not select the model, thresholds, V1 or explanation windows by special outputs.

1. Token evidence. Use the pinned general tokenizer `google-bert/bert-base-uncased` revision `b84905490c2d4796d85a42590c88a95af94cd5e2`, `transformers==4.44.2`, `max_length=50`, truncation and padding to 50, with special tokens. Require the generated input IDs, attention mask and segment IDs to match all three stored `text_bert` channels exactly for each official record. Use fast-tokenizer character offsets against that record's own `raw_text`; never import text by ID from another source. CLS, SEP, padding and punctuation without a lexical word have no acoustic word time. Matching BERT input tokens supports token-to-text position; it does not itself prove how the separate 50×768 continuous features were produced.
2. Acoustic evidence. Decode the record's matching official MP4 first audio stream to mono 16 kHz PCM16 with the already registered FFmpeg binary, preserving stream timestamps via `-copyts` and `ashowinfo`. Reject discontinuous audio PTS. Lowercase and tokenize the same official transcript with `[a-z]+(?:'[a-z]+)*|[0-9]+`, retaining punctuation as nonword text spans. Use the registered PocketSphinx 5.1.1 English model/dictionary and `set_align_text`; reject dictionary OOV, incomplete/reordered tokens, invalid/nonmonotonic/zero-length/out-of-audio bounds. Do not invent pronunciations or time for rejected words. No uniform word timing.
3. Video evidence. Decode actual first-video-stream presentation timestamps with FFmpeg `showinfo`; require monotonic PTS. A word interval is an estimated acoustic interval, and nearby video frames are selected by actual PTS. File-stem matching is a source association, not a proof that official 74/35-dimensional feature rows are exact acoustic/frame extraction windows.
4. Join. A normal WordPiece token receives the aligned word interval only when its tokenizer character span lies within exactly one regex word span and that word passed the acoustic check. Subwords share that word interval. A selected width-three feature window lists its eligible word intervals; merge only overlapping/adjacent intervals, retain separated intervals as a list, and leave special/padding/nonword tokens separately null. A window of only special/padding/nonword tokens has no timestamp. No `i/50 × duration` or nominal-FPS conversion.
5. Quality. `VERIFIED_TOKEN_TEXT_MAPPING` means exact local tokenizer-to-stored-token agreement and character offsets only. `ESTIMATED_ACOUSTIC_ALIGNMENT` means actual audio was aligned and passed mechanical checks, not human or official timestamp truth. `HUMAN_CHECKED_ESTIMATE` requires a real team member's recorded check; AI cannot assign it. `TEXT_SPAN_ONLY`, `PARTIAL`, and `UNMAPPABLE` retain failures. The `ASSUMED_INDEX_CONVENTION` flag remains until TRAIN/VALID BERT replay and an independent technical check support the continuous-feature positional correspondence. Report counts by record and selected window; never convert an estimated time into `OFFICIAL_TIMESTAMP`.

The existing S04 width-three deletion changes T/A/V contents together, so mapped old windows are **shared-window evidence**. They are not independent per-modality temporal attributions. If per-modality local evidence is added, fix the same width/reference/target before executing each modality separately and retain the old windows unmodified. Preserve support, original observation, structural zero, artificial corruption and V1 proxy as distinct concepts. All source text, sample identifiers, token IDs, word intervals, audio/frame cards and output CSVs remain private; public receipts contain only aggregate status, code/model/input hashes and actual checks.
