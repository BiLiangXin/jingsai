## Attachment3: clean replay passes, special interface remains blocked

The three `text_bert` channels were checked by values, not dtype. All 30 aligned special records have a finite float32 `(1,3,50)` container with integral token IDs in the BERT vocabulary, a binary nonempty prefix support channel and zero segment channel. The sole serialized `test` wrapper is a container name, not the Attachment2 TEST split. The public audit only counts positions; it does not include token sequences, transcript or identifiers.

The first preregistered strict clean replay (`atol=1e-5`, `rtol=1e-4`) failed at a few near-zero coordinates on TRAIN16/VALID8, while class outputs agreed 24/24 with frozen M2. Same-weight CPU versus GPU differences reached `3.47e-4`, larger than the candidate versus original. Before the **separate** expanded range, a backend envelope of `atol=5e-4, rtol=1e-4` was fixed; it is reported as an engineering numerical tolerance, not exact byte reproduction. Expanded TRAIN ordinals16–79 and VALID8–39 pass it on active positions; M2 class outputs agree 96/96, maximum logits change `3.40e-6` and maximum regression change `1.91e-6`. This is a clean-interface result only. No TEST rows were indexed and no labels entered preprocessing or selection. The monolithic Attachment2 pickle materializes its container on deserialization, so the statement is limited to field/index access, not an impossible claim that TEST bytes were never loaded.

The decisive gap is missingness: full Attachment2 TRAIN/VALID have **zero** in-support ID-100 tokens across 102,300 supported positions; the 30 aligned Attachment3 records have **131** such tokens in 27 records across 665 supported positions. This pattern is consistent with text corruption but does not prove the exact original feature-generation order or that each ID-100 is a reliable artificial corruption mask. Re-encoding these tokens yields nonzero contextual embeddings; simply routing them to frozen M2/V1 could misstate observation, whereas zeroing them after encoding changes the original representation and surrounding context. The clean replay therefore does not license a 30-row CSV. `ATTACHMENT3_CSV=NOT_GENERATED`, `ATTACHMENT3_ROWS=null`, and no old M2 metrics are assigned to a changed pipeline.

`NEW_PIPELINE_REQUIRED` if the original extractor/missingness semantics cannot be supplied: freeze one pinned general encoder and explicit corruption-to-observation rule; encode Attachment2 TRAIN and VALID with that same rule and Attachment3 through the same frontend; train an **independent** M2-E1 only after new authorization, then select and report on TRAIN/VALID under its own configuration. Keep the old M2 and its metrics immutable. No M2-E1 fit occurred here. The precise remaining organizer question is in `OFFICIAL_QUESTIONS.md`.

## Attachment4: fixed predictions, partial material mapping

The original 20-row private partial CSV remains byte-identical (SHA256 `6e4cfbb3407d5ccf62ad06aec3907277bf632e65a87ebbc20fa94d707ddb4187`). Re-tokenizing each record's own official text reproduces all three stored BERT channels for 20/20 aligned records. A separate pinned-BERT replay compares the active continuous text rows for all 20 (604 positions) and passes the fixed backend envelope, maximum coordinate difference `1.2446e-4`. This supports **text feature index → token/text span** for the fixed candidate. It does not prove how the official 74/35-dimensional audio/vision vectors were extracted or assign their precise time support.

The mapping method was written in `SOURCE_MAPPING_METHOD.md` before acoustic execution. A registered FFmpeg binary decodes the matching official MP4 audio with actual audio PTS and collects monotonic first-video-stream PTS. PocketSphinx 5.1.1 with the registered English model aligns the record's own words. Exact token order, positive/bounded monotonic word intervals, dictionary coverage and actual video PTS are checked. BERT specials, padding and nonword spans retain null time. Width-three windows list disjoint eligible word intervals; no `index/50 × duration`, nominal FPS or uniform word timing is used. These are shared T/A/V deletion windows, not modality-specific causal evidence.

The new private mapped **PARTIAL** CSV has 20 rows and preserves every original prediction/attribution column exactly. Twelve records and 72 selected windows have `ESTIMATED_ACOUSTIC_ALIGNMENT`; eight records and 48 windows have `TEXT_SPAN_ONLY` (four dictionary OOV, two no aligner segment, two token-sequence mismatch). There are zero human-checked word alignments and zero official timestamp-truth claims. This is a reproducible estimate, not complete Gate B delivery.
